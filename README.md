# AqylRoute AI

**Команда:** Название: MedRoute
Участники: Нұрсұлтан Талғатұлы, Алихан Жайшылық, Нұрлыхан Қақпан, Назым Орынбай, Нұрбол Жәни, Ердаулет Айтбай

## Проблема

Семья ребёнка с особыми потребностями сама собирает маршрут между образованием, здравоохранением и
соцзащитой: какие услуги положены, в каком порядке, какие документы, какие сроки. Шаги теряются,
сроки срываются, а пособие по инвалидности задним числом не назначается.

## Решение

Родитель проходит интервью из 8–12 вопросов. Правила (не ИИ) по проверенному каталогу из 21
госуслуги решают, какие шаги нужны, в каком порядке, с какими документами и нормативными сроками.
ИИ только разбирает ответы своими словами и пишет понятные пояснения; фильтр не пропускает диагнозы.
Куратор проверяет и утверждает план, видит просрочки и готовит обращение в организацию.

## Демо

- Фронтенд: _ссылка Vercel_
- API: _ссылка Railway_ (`/docs` — Swagger)
- Вход после `python seed.py --yes`, пароль у обоих `demo12345`:
  - родитель — `+7 700 000 00 01`
  - куратор — `+7 700 000 00 02`
- В кабинете куратора дата симулируется: по умолчанию 11 сентября — Амина просрочила зачисление в школу
  на 12 дней (красный), Алихан — ПМПК на 5 дней (жёлтый).

## Роли

| Роль | Как появляется аккаунт | Куда попадает после входа |
|---|---|---|
| `parent` — родитель | Регистрируется в приложении по SMS-коду | Кабинет родителя (`/parent`) |
| `curator` — куратор | Создаёт администратор скриптом `create_curator.py` | Кабинет куратора (`/curator`) |

- Роль хранится в колонке `role` таблицы `users`; отдельной таблицы для кураторов нет.
- Роли не переключаются: на главной странице нет выбора «родитель / куратор», каждый сразу попадает в
  свой кабинет. Чужие страницы перенаправляют в свой кабинет, чужие разделы API отвечают 403.
- Номер родителя нельзя сделать кураторским, и наоборот: для куратора нужен отдельный номер.
- Родитель видит только свои обращения, а план — только после утверждения куратором. В утверждённом
  плане он отмечает выполненные шаги (и может отменить свою отметку); сроки и приоритеты меняет только куратор.
- Аккаунта администратора в приложении нет: администратор — тот, у кого есть доступ к базе
  (`DATABASE_URL`) и кто запускает скрипты ниже.

### Создать куратора

Запускается из `backend/`. Куратор создаётся в той базе, что указана в `DATABASE_URL` в `backend/.env`
(локально — ваша Supabase; для продакшена — продакшен-база).

Параметры: `--phone`, `--last-name`, `--first-name` — обязательные; `--middle-name` и `--password` —
по желанию. Номер можно писать в любом виде: `+7 701 234 56 78`, `87012345678`, `7012345678`.

**Пример: создаём куратора Айгерим Сериковну Иванову**

```text
PS C:\...\haqaton-037\backend> python scripts/create_curator.py --phone "+7 701 234 56 78" --last-name Иванова --first-name Айгерим --middle-name Сериковна
Пароль куратора:          ← вводится скрыто, от 8 символов
Ещё раз:
Создан куратор Иванова Айгерим, телефон +77012345678
```

Теперь Айгерим открывает http://localhost:3000/login (или ссылку Vercel), вводит `+7 701 234 56 78` и
свой пароль — и сразу попадает в «Кабинет куратора». В Supabase в таблице `users` появилась строка с
`role = curator`.

**Сменить пароль куратору** — тот же запуск с тем же номером:

```text
PS ...\backend> python scripts/create_curator.py --phone "+7 701 234 56 78" --last-name Иванова --first-name Айгерим
Пароль куратора:
Ещё раз:
Обновлён куратор Иванова Айгерим, телефон +77012345678
```

**Без вопросов о пароле** (например, в скрипте) — через `--password`. Пароль останется в истории
команд терминала, поэтому для настоящих кураторов лучше вводить его по запросу:

```bash
python scripts/create_curator.py --phone "+7 701 234 56 78" --last-name Иванова --first-name Айгерим --password "Kurator2026!"
```

**Возможные ошибки:**

| Сообщение | Что делать |
|---|---|
| `Номер +77012345678 уже зарегистрирован как родитель. Для куратора нужен другой номер.` | Роли не переключаются — укажите другой номер |
| `Пароль короче 8 символов` | Придумайте пароль подлиннее |
| `Пароли не совпадают` | Повторите ввод |
| `Введите номер в формате +7 XXX XXX XX XX` | Проверьте номер: 10 цифр после +7 |

Добавлять кураторов вручную в Supabase Table Editor не нужно: пароль хранится в виде хеша, его делает скрипт.

### Проверить, у кого какая роль

Supabase → Table Editor → `users`, колонка `role`, или SQL Editor:

```sql
select last_name, first_name, phone, role from users order by role;
```

В приложении роль приходит в `GET /auth/me` (`"role": "parent"` или `"curator"`).

Колонка `role` добавляется в существующую таблицу `users` автоматически при первом запуске бэкенда
(или `seed.py`, `create_curator.py`); все уже зарегистрированные аккаунты становятся родителями.

## Запуск локально

Требования: Python 3.12+, Node 20+.

**Бэкенд** (терминал 1):

```bash
cd backend
python -m pip install -r requirements-dev.txt
cp .env.example .env          # PowerShell: Copy-Item .env.example .env — затем заполните
python seed.py --yes          # демо-данные; на SQLite можно без --yes
uvicorn main:app --reload     # http://localhost:8000/docs
```

**Фронтенд** (терминал 2):

```bash
cd frontend
npm ci
npm run dev                   # http://localhost:3000
```

Откройте http://localhost:3000/login:
- **Родитель** — `+7 700 000 00 01` / `demo12345` или новый аккаунт через «Зарегистрироваться».
- **Куратор** — `+7 700 000 00 02` / `demo12345` или свой, созданный `create_curator.py`.

`seed.py --yes` удаляет все случаи, планы, ответы и события в базе из `DATABASE_URL` (пользователи
остаются), затем создаёт демо-родителя, демо-куратора и два утверждённых случая. Чтобы сохранить свои
данные, пропустите его и создайте куратора скриптом.

**Тесты и проверка каталога:**

```bash
cd backend
python -m pytest                    # тесты работают на временной SQLite и не трогают Supabase
python scripts/validate_catalog.py
```

### Настройки (`.env`)

- Бэкенд читает `backend/.env`. `.env.example` — только шаблон, код его не читает. `.env` не попадает в git.
- Фронтенд без файла настроек обращается к `http://localhost:8000`. Другой адрес — в
  `frontend/.env.local`: `NEXT_PUBLIC_API_URL=...`.

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | Supabase **Session pooler** (IPv4). Для работы без Supabase: `sqlite:///./aqylroute.db` |
| `JWT_SECRET` | случайная строка: `python -c "import secrets; print(secrets.token_urlsafe(32))"` |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | ИИ для ответов своими словами и пояснений, например `gpt-4o` |
| `SMSC_LOGIN`, `SMSC_PASSWORD`, `SMSC_SENDER` | SMS через smsc.kz; пусто — коды печатаются в лог бэкенда |
| `CORS_ORIGINS` | адреса фронтенда через запятую |
| `CORS_ORIGIN_REGEX` | необязательно, для превью Vercel |

Без `OPENAI_API_KEY` всё работает: тексты плана берутся из каталога, а ответ своими словами просит
выбрать вариант.

## API по ролям

Полный список — в Swagger (`/docs`).

| Кто | Эндпоинты |
|---|---|
| Все | `POST /auth/register/send-code`, `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `GET /services`, `GET /health` |
| Родитель | `POST /cases`, `GET /cases/{id}/interview`, `POST /cases/{id}/answers`, `GET /parent/cases`, `POST /parent/cases/{id}/plan` (отправить интервью), `GET /parent/cases/{id}` (план после утверждения), `PATCH /parent/cases/{id}/steps/{step_id}` (`{"done": true}` — шаг выполнен, `false` — отменить свою отметку) |
| Куратор | `GET /cases`, `GET /cases/{id}`, `POST /cases/{id}/plan` (`?regenerate=true`), `PATCH /plans/{id}/steps/{step_id}`, `POST /plans/{id}/steps`, `POST /plans/{id}/approve`, `POST /plans/{id}/steps/{step_id}/escalate` |

Просрочки считаются на дату `?today=YYYY-MM-DD` (по умолчанию — сегодня); её задаёт «Симулировать дату».

## Деплой

### Бэкенд — Railway

1. New Project → Deploy from GitHub repo → этот репозиторий.
2. Service → Settings:
   - **Root Directory:** `backend`
   - **Config file:** `/backend/railway.json` (старт `uvicorn main:app --host 0.0.0.0 --port $PORT`,
     healthcheck `/health`; Python 3.13 из `backend/.python-version`)
   - **Region:** Азия (база Supabase в Токио)
3. Variables — те же, что в таблице выше, значения из своего `.env`, но:
   - `JWT_SECRET` — новая случайная строка, не `change-me`;
   - `CORS_ORIGINS` — домен Vercel, например `https://<проект>.vercel.app` (без `/` в конце).
4. Settings → Networking → Generate Domain. Проверка: `https://<app>.up.railway.app/health` → `{"status":"ok"}`.
   Таблицы и колонка `role` создаются при первом старте.

### Фронтенд — Vercel

1. Add New → Project → этот репозиторий.
2. **Root Directory:** `frontend` (фреймворк Next.js определится сам).
3. Environment Variables: `NEXT_PUBLIC_API_URL=https://<app>.up.railway.app` (без `/` в конце).
   Переменная вшивается при сборке: после её изменения нужен Redeploy.
4. Deploy, затем впишите полученный домен в `CORS_ORIGINS` на Railway.

### Демо-данные, кураторы и проверка

С `DATABASE_URL` продакшена в `backend/.env`:

```bash
cd backend
python seed.py --yes                   # демо-случаи, демо-родитель и демо-куратор
python scripts/create_curator.py ...   # настоящие кураторы
python scripts/smoke.py --api https://<app>.up.railway.app --web https://<проект>.vercel.app
```

`smoke.py` ничего не меняет и проверяет:
- здоровье API и каталог из 21 услуги;
- вход демо-родителя и демо-куратора, запрет чужих разделов для каждой роли;
- обе просрочки на демо-дату и нагрузку куратора;
- что родитель видит утверждённый план без пояснений куратора;
- отказ 422 на услугу вне каталога;
- загрузку фронтенда и CORS.

### Чек-лист на живых ссылках (вручную)

- [ ] Регистрация с SMS-кодом и вход по паролю; новый пользователь попадает в кабинет родителя
- [ ] Куратор, созданный `create_curator.py`, входит и попадает в кабинет куратора
- [ ] На главной нет выбора роли; родитель, открывший `/curator`, возвращается в свой кабинет
- [ ] Родитель → новое интервью: 8–12 вопросов, у каждого «Не знаю»
- [ ] После последнего ответа — «Составляем план…», затем «План на проверке у куратора»
- [ ] Родитель не видит план до утверждения
- [ ] Куратор: бейджи просрочки (жёлтый 1–7 дн., красный > 7), метрика нагрузки
- [ ] «Симулировать дату» меняет просрочки
- [ ] Правка статуса, приоритета и срока шага; добавление шага только из каталога
- [ ] Утверждение → план появляется у родителя, просрочка показана нейтрально
- [ ] Родитель отмечает шаг выполненным и может отменить свою отметку; куратор видит «Отмечено родителем»
- [ ] Эскалация: готовый текст; для пособия — предупреждение, что оно не назначается задним числом
- [ ] В текстах нет диагнозов и степеней

## Структура проекта

- `backend/data/` — каталог: `services.json` (услуги, документы, НПА), `rules.json` (правила),
  `facts.json` (словарь фактов), `questions.json` (банк вопросов)
- `backend/services/` — `eligibility.py` (правила), `interview.py`, `planner.py`, `safety.py`
  (фильтр диагнозов), `overdue.py`, `llm.py`, `auth.py` (вход и проверка ролей)
- `backend/routers/` — API: `auth`, `cases` (интервью и кабинет куратора), `plans`, `parent`, `services`
- `backend/models.py` — таблицы: `users` (с ролью), `cases`, `interview_answers`, `plans`, `events`
- `backend/seed.py` — демо-данные; `backend/scripts/` — `create_curator.py`, `validate_catalog.py`, `smoke.py`
- `frontend/app/` — страницы: `/` (перенаправляет по роли), `/login`, `/register`, `/parent`,
  `/parent/[caseId]`, `/curator`, `/curator/cases/[id]`
- `frontend/lib/api.ts` — все запросы к API

## Что готово

Интервью, план по правилам с ИИ-пояснениями и запасными текстами из каталога, фильтр диагнозов,
утверждение куратором, правка и добавление шагов, отметка выполненных шагов родителем,
просрочки с симуляцией даты, эскалация,
роли родителя и куратора, демо-данные, деплой-конфиг.

Ограничения:
- Сроки нормативные; праздничные дни не учитываются, только выходные.
- Кураторы видят все случаи: закрепления случаев за кураторами пока нет.
- Куратор не может править тексты шагов и удалять шаги — только статус, приоритет, срок и добавление.
- Администратора в приложении нет: кураторов создают скриптом.
- smsc.kz не доставляет на номера Beeline (ошибка 248) — для демо коды в логе или номера Kcell/Tele2.
- Правила и тексты вопросов — черновик, до показа семьям их вычитывает практикующий соцработник.
