# AqylRoute AI

**Команда:** название и участники

## Проблема

Семья ребёнка с особыми потребностями сама собирает маршрут между образованием, здравоохранением и
соцзащитой: какие услуги положены, в каком порядке, какие документы, какие сроки. Шаги теряются,
сроки срываются, а пособие по инвалидности задним числом не назначается.

## Решение

Родитель проходит интервью из 8–12 вопросов. Правила (не ИИ) по проверенному каталогу из 21
госуслуги решают, какие шаги нужны, в каком порядке, с какими документами и нормативными сроками.
ИИ только разбирает ответы своими словами и пишет понятные пояснения; фильтр не пропускает диагнозы.
Куратор проверяет и утверждает план, видит просрочки и готовит обращение в организацию.

## Демо

- Фронтенд: _ссылка Vercel_
- API: _ссылка Railway_ (`/docs` — Swagger)
- Вход: `+7 700 000 00 01`, пароль `demo12345` (после `python seed.py --yes`)
- В кабинете куратора дата симулируется: по умолчанию 11 сентября — Амина просрочила зачисление в школу
  на 12 дней (красный), Алихан — ПМПК на 5 дней (жёлтый).

## Запуск локально

Требования: Python 3.12+, Node 20+.

```bash
cd backend
python -m pip install -r requirements-dev.txt
cp .env.example .env          # заполните DATABASE_URL (или sqlite:///./aqylroute.db), OPENAI_API_KEY, JWT_SECRET
python seed.py                # на SQLite; для Postgres: python seed.py --yes (удаляет все случаи)
uvicorn main:app --reload     # http://localhost:8000/docs
python -m pytest              # тесты
python scripts/validate_catalog.py
```

```bash
cd frontend
npm ci
cp .env.example .env.local    # NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev                   # http://localhost:3000
```

Без `OPENAI_API_KEY` всё работает: тексты плана берутся из каталога, ответы своими словами просят
выбрать вариант. Без `SMSC_LOGIN` SMS-коды печатаются в лог бэкенда.

## Деплой

### Бэкенд — Railway

1. New Project → Deploy from GitHub repo → этот репозиторий.
2. Service → Settings:
   - **Root Directory:** `backend`
   - **Config file:** `/backend/railway.json` (старт `uvicorn main:app --host 0.0.0.0 --port $PORT`,
     healthcheck `/health`; Python 3.13 из `backend/.python-version`)
   - **Region:** Азия (база Supabase в Токио)
3. Variables (значения — из своего `.env`, не из примера):

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | Supabase **Session pooler** (IPv4), не Direct connection |
   | `JWT_SECRET` | случайная строка: `python -c "import secrets; print(secrets.token_urlsafe(32))"` |
   | `CORS_ORIGINS` | `https://<проект>.vercel.app` (домен фронтенда, через запятую, без `/` в конце) |
   | `CORS_ORIGIN_REGEX` | необязательно, для превью Vercel: `https://<проект>-.*\.vercel\.app` |
   | `OPENAI_API_KEY`, `OPENAI_MODEL` | ключ и модель, например `gpt-4o` |
   | `SMSC_LOGIN`, `SMSC_PASSWORD`, `SMSC_SENDER` | smsc.kz; пусто — коды в логе Railway |

4. Settings → Networking → Generate Domain. Проверка: `https://<app>.up.railway.app/health` → `{"status":"ok"}`.
   Таблицы создаются при первом старте.

### Фронтенд — Vercel

1. Add New → Project → этот репозиторий.
2. **Root Directory:** `frontend` (фреймворк Next.js определится сам).
3. Environment Variables: `NEXT_PUBLIC_API_URL=https://<app>.up.railway.app` (без `/` в конце).
   Переменная вшивается при сборке: после её изменения нужен Redeploy.
4. Deploy, затем впишите полученный домен в `CORS_ORIGINS` на Railway.

### Демо-данные и проверка

```bash
cd backend
python seed.py --yes          # с DATABASE_URL продакшена в .env; удаляет все случаи, пользователей оставляет
python scripts/smoke.py --api https://<app>.up.railway.app --web https://<проект>.vercel.app
```

`smoke.py` ничего не меняет и проверяет: здоровье API, каталог из 21 услуги, вход демо-родителя,
обе просрочки на демо-дату, нагрузку куратора, скрытие пояснений куратора от родителя, отказ 422 на
услугу вне каталога, загрузку фронтенда и CORS.

### Чек-лист на живых ссылках (вручную)

- [ ] Регистрация с SMS-кодом и вход по паролю
- [ ] «Я родитель» → новое интервью: 8–12 вопросов, у каждого «Не знаю»
- [ ] После последнего ответа — «Составляем план…», затем «План на проверке у куратора»
- [ ] Родитель не видит план до утверждения
- [ ] «Я куратор»: бейджи просрочки (жёлтый 1–7 дн., красный > 7), метрика нагрузки
- [ ] «Симулировать дату» меняет просрочки
- [ ] Правка статуса, приоритета и срока шага; добавление шага только из каталога
- [ ] Утверждение → план появляется у родителя, просрочка показана нейтрально
- [ ] Эскалация: готовый текст; для пособия — предупреждение, что оно не назначается задним числом
- [ ] В текстах нет диагнозов и степеней

## Структура проекта

- `backend/data/` — каталог: `services.json` (услуги, документы, НПА), `rules.json` (правила),
  `facts.json` (словарь фактов), `questions.json` (банк вопросов)
- `backend/services/` — `eligibility.py` (правила), `interview.py`, `planner.py`, `safety.py`
  (фильтр диагнозов), `overdue.py`, `llm.py`
- `backend/routers/` — API: `auth`, `cases` (интервью, план, кабинет куратора), `plans`, `parent`, `services`
- `backend/seed.py` — демо-данные; `backend/scripts/` — `validate_catalog.py`, `smoke.py`
- `frontend/app/` — страницы: `/`, `/parent`, `/parent/[caseId]`, `/curator`, `/curator/cases/[id]`
- `frontend/lib/api.ts` — все запросы к API

## Что готово

Интервью, план по правилам с ИИ-пояснениями и запасными текстами из каталога, фильтр диагнозов,
утверждение куратором, правка и добавление шагов, просрочки с симуляцией даты, эскалация,
демо-данные, деплой-конфиг.

Ограничения:
- Сроки нормативные; праздничные дни не учитываются, только выходные.
- Роли в демо не разделены: куратором может войти любой пользователь.
- smsc.kz не доставляет на номера Beeline (ошибка 248) — для демо коды в логе или номера Kcell/Tele2.
- Правила и тексты вопросов — черновик, до показа семьям их вычитывает практикующий соцработник.
